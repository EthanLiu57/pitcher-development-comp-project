# Modeling Pitcher Development Through Clustering and Simulation

A data pipeline and interactive application for identifying minor league pitcher development comparables using pitch characteristic distributions rather than performance statistics.

---

## Motivation

Traditional minor league statistics are noisy proxies for major league potential. Park effects, opponent quality, and the uneven developmental pace of players at different levels all contaminate performance-based evaluations. This project takes a different approach: **ignore outcomes entirely and focus on how a pitcher throws**.

The core idea is that a pitcher's arsenal — the physical characteristics of each pitch type — can be modeled as a multivariate distribution, and that similarity in those distributions across pitchers provides a more stable basis for developmental comparison. If a young minor league pitcher's stuff resembles that of pitchers who went on to have successful major league careers, that signal may be more durable than ERA or WHIP.

## Pipeline Overview

The project has four main stages:

**1. Data Collection (Python / Selenium)**
Minor league pitch-level data was scraped from Baseball Savant's Statcast minor league search. The scraper navigates the results table, downloads per-pitcher CSVs, and handles session failures, duplicate detection, and automatic retry. A second script pipes the downloaded CSVs directly into a SQLite database.

**2. Feature Engineering and Storage (R / SQLite)**
Raw Statcast fields were used to derive 16 pitch characteristics per pitch type, including velocity, spin rate, Bauer units, spin efficiency, induced vertical break, horizontal break, movement angle, vertical and horizontal approach angle, and release position. For each pitcher-year-pitch type combination, a kernel density estimate was computed over a 50-point grid for each metric and stored in a structured SQLite database alongside summary statistics.

**3. Similarity and Simulation (R)**
An initial approach represented each pitcher's metrics as point estimates using a James-Stein shrinkage estimator, but this was replaced by the full distributional representation to better capture the shape of each pitcher's stuff rather than just its center. Pairwise distributional distances were computed using the Hellinger distance between KDEs as the primary metric, with a weighted Euclidean combination across metrics. Distance matrix computation was parallelized to handle the scale of the dataset. Similar pitchers were identified for each target, and Monte Carlo simulations of future pitch characteristic distributions were generated by sampling from the trajectories of those comparable pitchers.

**4. Interactive Application (R / Shiny)**
Results were pre-computed and stored in a simulation database for fast retrieval. A Shiny dashboard — the *Pitcher Development Lab* — allows users to select a pitcher and year, view their current pitch distributions, see their closest comparables, and examine simulated future distributions with uncertainty bands.

## Key Methodological Finding

The clustering results revealed that **minor league pitcher stuff does not organize cleanly into discrete clusters**. Across all pitch types and distance metrics tried, hierarchical clustering produced weak cluster structure with high within-cluster variance — the pitch characteristic space appears to be more of a continuous manifold than a set of distinct pitcher archetypes.

This is itself an informative result. It suggests that pitcher similarity is better thought of as a continuous spectrum than a discrete taxonomy, and has implications for how tools like this should be designed: nearest-neighbor retrieval and simulation are likely more appropriate than cluster-based grouping for this kind of application.

## Limitations and Future Directions

- **Dimensionality**: With 13 metrics across multiple pitch types per pitcher, the distance space is high-dimensional and clustering is correspondingly weak. Dimensionality reduction (PCA or UMAP on the KDE grid values) before clustering is a natural next step.
- **Data availability**: PitchFX data for earlier years was not available through the scraping approach used, limiting the historical depth of the comparable pool.
- **App deployment**: Memory requirements for the pre-computed simulation database exceeded Shinyapps.io's free tier limits. A production version would benefit from a more efficient storage format or a server-side database.
- **Missing data**: Some pitcher-year combinations had incomplete metric coverage due to pitch types with too few observations, leading to gaps in the comparable pool.
- **Add New Pitcher**: When adding a pitcher, it is not currently possible to find similar pitchers or perform simulation, only viewing current stuff is available
